# Magnet-запросы (версия 1.9.1.0)

Зачем: другая программа (ps4installer, вкладка «Запрос на игры») или человек со страницы должны уметь поставить раздачу в очередь
по одному хэшу, без файла `.torrent` (рутрекер выдаёт `.torrent` только под логином и не больше ~200 в сутки, а файл содержит личный ключ).

## Как это работает
1. Запрос: `GET /api/add_magnet?magnet=<ссылка, закодированная как параметр>[&drive=internal|N]`. Ответ сразу:
   `{"ok":true,"hash":"<40 hex>","pending":true,"already_queued":false}`.
   Служба кладёт в папку накопителя (по умолчанию как для `/api/add`: `/data/pkg/torrents` или `/mnt/usbN/torrents`) файл
   **`<хэш>.magnet`** (одна строка: сама ссылка). Если раздача уже в списке и не завершена: `{"ok":true,"duplicate":true,...}`, файл не создаётся.
   Битая ссылка: 400.
2. Фоновый поток (`magnet_thread` в `main.cpp`, раз в 5 с и по запросу) берёт `*.magnet` из верхнего уровня папок накопителей:
   `tracker_announce_http` по трекерам из ссылки (нет трекеров: `http://bt.t-ru.org/ann?magnet`) -> список пиров ->
   `metadata_fetch` (`metadata.cpp`): до 6 потоков, до 60 пиров, handshake с битом расширений, BEP 10 (`ut_metadata`), BEP 9 (куски по 16 КБ),
   проверка SHA-1 всего описания по хэшу -> `magnet_build_torrent` (`magnet.cpp`) собирает обычный `.torrent` (байты `info` как есть,
   `announce`, `announce-list`) -> проверка `load_torrent` -> файл `<имя раздачи>.torrent` в той же папке -> `.magnet` удаляется ->
   прежнее сканирование `scan_usb` подхватывает торрент (дальше всё как с загруженным вручную `.torrent`; автозапуск по настройке).
3. Нет сети / трекер молчит / пиров нет / хэш не сошёлся: `.magnet` остаётся, попытки всё реже (40 с, 80 с, ... до 20 минут).
   Это и есть режим «ждёт сети»: консоль может быть офлайн неделями, запросы копятся.
4. Состояние: `GET /api/magnets` -> `{"magnets":[{"hash","fails","fetching","error"}]}` (только ожидающие). Правило для клиентов:
   есть `<хэш>.magnet` или хэш в `/api/magnets` = ждёт; нет и раздача в `/status` = выполняется; нет нигде = выполнена и удалена/не было.
5. Файл со ссылками: любой файл `*.magnet` в корне папки торрентов (например `games.magnet`) читается так: в каждой строке ссылка
   `magnet:?...` или просто хэш (40 hex), пустые строки и строки с `#` пропускаются. Из каждой годной строки делается свой запрос
   `<хэш>.magnet`, сам файл удаляется (если годных строк нет, он переименовывается в `.bad`). Строка без трекера использует трекер по умолчанию.
6. Кнопка «+ magnet» на веб-странице (рядом с «+ link»): спрашивает ссылку и вызывает `/api/add_magnet`. Тексты `btn_magnet`, `magnet_*`
   есть в `ru.json` и по-английски во всех остальных языковых файлах (переводы можно уточнить; без перевода берётся английский).
7. Неправильный файл `.magnet` переименовывается в `.magnet.bad`.

## Ограничения (сознательно)
* DHT нет, UDP-трекеров нет, только `http://` трекеры. Пиры только от трекера, входящие соединения для получения описания не используются.
* Описание не больше 1 МБ (`METADATA_MAX_BYTES`), как и `.torrent`, принимаемый со страницы.
* Раздачи с флагом private не отдают описание по BEP 9 (по правилам BEP 27): такой запрос будет бесконечно «ждать».
* Проверено на ПК (`tests/ft/magnet_run.sh`, 26/26, ASAN чист). На консоли не запускалось.
