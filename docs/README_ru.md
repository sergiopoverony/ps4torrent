# ps4torrentd — торрент-клиент без экрана (ps4-payload-sdk)

Работает фоновой программой, управляется через браузер: `http://IP_КОНСОЛИ:8787/`

## Папки на флешке (любой разъём usb0 ... usb7)

    /mnt/usbN/torrents/             сюда кладёшь .torrent (читается только этот уровень)
    /mnt/usbN/torrents/downloads/   сюда качается
    /mnt/usbN/torrents/complete/    сюда уходит .torrent после завершения
    /mnt/usbN/torrents/.state/      служебное: прогресс докачки (чтобы пережить перезапуск)


* Флешку можно вынуть и воткнуть в другой разъём: раздача узнаётся по хэшу и продолжается.
* Убрал .torrent из папки вручную -> раздача забывается (скачанные файлы остаются).
* Положил готовый .torrent заново -> качается заново (файлы пересчитываются и докачиваются).

## Сборка и отправка (Lubuntu / Linux с ps4-payload-sdk)

    export PS4_PAYLOAD_SDK=/opt/ps4-payload-sdk
    make
    make send PS4_HOST=192.168.0.24        # порт по умолчанию 9090 (BinLoader GoldHEN)

## Сборка и прошивки

* Программа собирается на **`ps4-payload-dev/sdk`** (`https://github.com/ps4-payload-dev/sdk`, ветка `master`, коммит `573b4a0` и новее).
  SDK надо собрать и установить, затем **один раз собрать библиотеку C++**: `bash libcxx.sh` из папки SDK (нужен `cmake`; без неё сборка
  проекта падает с «`'string' file not found`»). Дальше `export PS4_PAYLOAD_SDK=<куда установили>` и `make` в папке проекта.
* **Ограничение по версии прошивки задаёт стартовый код SDK:** версии ниже **3.50** не поддерживаются; для известных версий (3.50 ... 14.00,
  включая 13.52) в SDK есть готовая таблица, для более новых используется поиск по шаблонам. Если инициализация не удалась, программа молча
  завершается до запуска (в `log.txt` ничего не появится). На консоли проверено только на **13.52** с GoldHEN 2.4b18.

## Веб-страница

Нажатие кнопки сразу показывает «...», и пока команда выполняется, список не перерисовывается сам (раньше замена
списка каждые 2 секунды могла «съесть» нажатие и вернуть кнопку в исходный вид). Повторные нажатия на ту же
кнопку игнорируются, список не заменяется под пальцем (0,7 с после нажатия), а если консоль не ответила за 10 секунд,
кнопка освобождается с сообщением об ошибке. Внизу страницы: `ps4torrent v<версия> Created by SergioPoverony and Mr.Claude` (версия берётся из программы, сейчас 1.4.1.6; при каждой пересборке последняя цифра растёт). Оформление только тёмное (в том числе
выпадающие списки).

## Управление и API

Страница `http://IP:8787/` — список раздач, пауза и продолжение, удаление, добавление `.torrent` с этого
устройства (кнопка «+ .torrent»), настройки. Всё то же самое доступно запросами (для PKG-интерфейса):

| Запрос | Что делает |
|---|---|
| `GET /status` | список раздач, флешки, скорость, `incoming`, `version` (JSON) |
| `GET /api/pause?hash=ХЭШ` | пауза (хэш можно сокращать до 8+ символов) |
| `GET /api/resume?hash=ХЭШ` | продолжить |
| `GET /api/pause_all`, `GET /api/resume_all` | поставить на паузу / запустить все раздачи (кроме готовых) |
| `GET /api/delete?hash=ХЭШ40` | убрать из списка; `.torrent` уходит в `removed/`, скачанные файлы остаются |
| `GET /api/delete?hash=ХЭШ40&files=1` | то же и **удалить скачанные файлы** (только из списка этого `.torrent`, только внутри `downloads/`; файлы, нужные другим раздачам, не трогаются). Нужен полный хэш (40 символов) | Файлы стираются в отдельном потоке: удаление больших файлов может занять минуты, но программа остаётся отзывчивой; завершение пишется в лог строкой `delete finished`.
| `POST /api/add?name=ИМЯ.torrent&drive=internal\|N&start=1\|0` | тело запроса — сам файл `.torrent` (до 1 МБ). `drive=internal` — память консоли, `drive=N` — флешка N; без `drive` берётся `save_to` из настроек (по умолчанию `internal`). `start=1` запустить сразу, `start=0` оставить на паузе, без `start` решает автозапуск. В ответе `root`, `autostart`, `started` |
| `GET /api/config` | `max_parallel`, `listen_port`, `listening`, `autostart`, `save_to`, `resume_session`, `token_set`, `version` |
| `GET /api/set?max_parallel=N&listen_port=P&autostart=0\|1&save_to=usb\|internal&resume_session=0\|1` | меняет настройки и записывает `config.txt` (порт переоткрывается сразу) |
| `GET /quit` | остановить программу (прогресс сохраняется) |

Ответы управляющих запросов: `{"ok":true}` или `{"ok":false,"error":"..."}` с кодом 4xx/5xx. Сервер отвечает
на пауза/продолжить/удалить/настройки **после того, как команда применена** и состояние обновлено (ждёт не больше
3 секунд), поэтому `/status`, запрошенный сразу после ответа, уже показывает новое состояние.

**Пароль (необязательно, по умолчанию его нет и ничего настраивать не нужно).** Если в `config.txt` есть `web_token=ПАРОЛЬ`, все запросы, кроме самой страницы,
должны содержать `&token=ПАРОЛЬ`; без него ответ 401. Страница сама спросит пароль (или откройте
`http://IP:8787/#token=ПАРОЛЬ`). Пароль передаётся по обычному HTTP без шифрования: он защищает от случайного
доступа в домашней сети, но не от прослушивания. Страницу управления наружу пробрасывать НЕ нужно.

## Иконки и логотип (вшиты в программу)

Три картинки лежат в папке `assets/` и при сборке (`make`) вшиваются в ELF (`assets.S`), поэтому на консоль ничего
раскладывать не нужно:

| Файл | Где используется |
|---|---|
| `assets/favicon.ico` | значок вкладки браузера (`/favicon.ico`); многоразмерный, 16–256 пикселей |
| `assets/title.png` | логотип в шапке страницы (`/logo.png`) |
| `assets/notify64.png` | иконка уведомлений, 64×64 PNG с прозрачностью (`/notify.png`) |

Заменить картинку: положить новый файл с тем же именем в `assets/` и собрать заново. Картинки отдаются без пароля,
как и сама страница.

**Иконка в уведомлениях на экране.** Система берёт иконку по адресу, поэтому программа отдаёт вшитую картинку своим
веб-сервером (`/notify.png`) и указывает в уведомлении адрес `http://127.0.0.1:8787/notify.png`. Этот способ проверен на
консоли и включён всегда; настраивать ничего не нужно. Сообщения о сбое программы (`CRASHED`) идут со стандартной
иконкой, потому что в этот момент веб-сервер уже может не работать.

## Несколько накопителей и создание папки torrents

К консоли может быть подключено несколько USB-накопителей (`/mnt/usb0`, `/mnt/usb1`, ...). В окне **Add torrent**
показываются **все смонтированные накопители**, в том числе те, где ещё нет папки `torrents`. Если выбрать такой
накопитель, программа при добавлении молча создаёт на нём папку `torrents` (и рабочие подпапки), после чего всё идёт
как обычно. Накопитель, смонтированный только для чтения,
помечается `(read-only: cannot be used)`.

* Пустая точка монтирования без накопителя не показывается: смонтированным считается тот накопитель, у которого
  номер устройства отличается от каталога `/mnt` (или в точке монтирования что-то лежит).
* API: `POST /api/add?...&drive=N` создаёт `torrents` на накопителе `N`, если её нет. Ошибки: `409` (накопитель не
  смонтирован), `500` (папку создать не удалось, например диск только для чтения; в тексте код ошибки), `400` (неверный номер).
  Без `drive` и при `save_to=usb` выбирается доступный для записи накопитель, где больше места (сначала среди тех, где
  `torrents` уже есть).
* В `/status` появилось поле `mounts`: `[{"n":1,"mount":"/mnt/usb1","has_torrents":false,"writable":true,"free":...,"total":...,"low":false}, ...]`.

## Память и скорость (версия 1.4.1.2)

* **Лимит активных кусков.** Одна раздача держит в памяти до 32 МБ кусков одновременно (раньше 8 МБ: при кусках по 8 МБ это были всего
  2 куска, и пиры без именно этих кусков простаивали). Защита по памяти: все буферы кусков всех раздач вместе (с очередью записи на диск)
  не больше 128 МБ; на раздачу всегда остаются минимум 2 куска. В журнале при запуске задачи строка `up to N pieces of X KB (Y MB) are held
  in memory at once`, в строке `alive:` и в `/status` (`buf_kb`) видно, сколько занято. Скорость от этого вырастет не обязательно:
  она может упираться в самих пиров.
* **Куча (обычная память, на консоли ~10 МБ).** Записи о кусках раздачи теперь создаются только для кусков в работе (раньше массив на все
  куски: 144 байта на кусок, у раздачи на 26 тысяч кусков 3,5 МБ, и три больших раздачи вместе с буферами соединений приводили к
  `std::bad_alloc` и остановке программы). На ПК три раздачи по 25 953, 11 187 и 7 670 кусков: 7,2 МБ куч-памяти -> 1,3 МБ.
  Буфер приёма соединения возвращает лишнюю память, за один проход читается не больше 256 КБ.
* **Нехватка памяти больше не останавливает программу:** все соединения с пирами сбрасываются (`!!! OUT OF MEMORY ... the program
  continues`), через ~5 секунд раздачи подключаются заново, приходит уведомление. Если так повторяется 5 раз за 10 минут, остановка чистая.
* **Быстрая проверка прогресса и снятые файлы.** Раньше у задач со снятыми файлами каждая пауза/продолжение и каждый перезапуск запускали
  полную проверку всех данных (для 100 ГБ больше часа): быстрая проверка требовала, чтобы снятые файлы лежали на диске. Исправлено.
* **Показ скорости на странице сглажен** (по 25% нового значения за обновление раз в 2 секунды, поверх сглаживания в консоли).

## Завершённые загрузки остаются в списке

Когда загрузка завершается, её `.torrent` переносится в `complete/`. После **перезапуска программы или консоли** такие раздачи снова
показываются в списке как `complete` (100%, с названием, размером и, если выбирались файлы, с меткой «2/3 files»), **пока вы их не
удалите**: `remove` (запись уходит из списка, `.torrent` переезжает в `removed/`, скачанные файлы остаются) или `remove + files`
(ещё и скачанные файлы удаляются). Так не потеряется название, даже если вы его забыли.

* Сразу после обновления в списке появятся и **все прежние завершённые раздачи**, чьи `.torrent` лежат в `complete/`. Лишние
  уберите кнопкой `remove`.
* Из-за малого объёма памяти на консоли показывается **не больше 100 завершённых раздач (и 3000 файлов в сумме)**, самые свежие
  первыми. Остальные остаются в папке `complete/` (в логе об этом строка `not all finished torrents ... are shown`).
* Если тот же `.torrent` положить в корень `torrents/` заново, раздача скачивается заново с полным набором файлов (прежний выбор
  файлов сбрасывается).

## Окна добавления (версия 1.4.1.6)

Кнопки отмены красные, «Далее» и «Start download» зелёные. Окно выбора файлов шире; сначала идут файлы корня, ниже папки отдельными блоками (галочка на папке отмечает все её файлы). Кнопка Back возвращает в первое окно, выбранные галочки сохраняются. Если такой торрент уже есть в списке (не завершён), он не добавляется повторно, и страница пишет «Already in the list, not added again»; завершённый торрент можно добавить заново.

## Выбор файлов раздачи (версия 1.3.0.0)

Если в раздаче несколько файлов, качать можно только нужные.

* **При добавлении** (кнопка «+ .torrent»): первое окно (место сохранения) заканчивается кнопкой **Next** справа от
  **Cancel**; у раздачи из одного файла вместо неё остаётся **Download**. **Next** открывает второе окно: список файлов
  с галочками (по умолчанию выбраны все), размеры, сумма выбранного и предупреждение о нехватке места по выбранному.
  Кнопки: **Select all**, **Deselect all**, **Start download**, **Cancel**. Если выбрано несколько торрентов, у каждого
  свой заголовок с общей галочкой, и Start недоступен, пока хотя бы в одной раздаче не выбрано ни одного файла.
* **Для уже добавленной задачи**: кнопка **files** (у незавершённых задач из нескольких файлов) открывает то же окно
  с кнопкой **Apply**. Рядом со статусом пишется «выбрано/всего files».
* Снятые файлы **не создаются** и не пишутся на диск. Куски на границе файлов (часть байтов в снятом файле) скачиваются
  целиком, но байты снятого файла не записываются. Размер, процент, время и проверка места считаются по нужным кускам.
* **Вернуть снятый файл** можно в любой момент: пограничные куски при этом скачиваются заново (иначе внутри файла
  остались бы «дыры»), остальное докачивается. **Снять файл** после начала загрузки: уже скачанное остаётся на диске.
  У завершённой задачи выбор менять нельзя.
* Выбор хранится рядом с прогрессом (`.state/<хэш>.sel`) и переживает перезапуск.
* API: `POST /api/add?...&skip=3,5-9` (номера **снятых** файлов, нумерация с нуля в порядке торрента; нельзя снять все;
  ошибки `400`), `GET /api/files?hash=H` (список файлов задачи: `i`, `path`, `size`, `sel`), `GET /api/select?hash=H&skip=3,5-9`
  (пустой `skip` = выбрать все). В `/status` у каждой задачи появились `nfiles` и `nskip`, а `size` и `pct` считаются
  по выбранному.

## Добавление торрента и выбор места сохранения

Кнопка **«+ .torrent»** на странице: выберите один или несколько файлов, и откроется окно **Add torrent**:

* список файлов с названием и размером (они читаются из самого `.torrent` прямо в браузере);
* выбор **«Save to»**. По умолчанию **память консоли (системный диск, `/data/pkg/torrents`)**; если подключена флешка,
  она есть в списке вместе со свободным местом;
* предупреждение, если на выбранном месте не хватит места (`Not enough free space ...`) или после загрузки
  останется меньше запаса (2 ГБ на флешке, 5 ГБ в памяти консоли);
* галочка **«Start downloading right away»** (включена по умолчанию) и кнопка **Download**. Нажатие добавляет файл в
  выбранное место и в общий список; с галочкой загрузка стартует сразу (это явное действие, оно важнее общей
  настройки «автозапуск»), без галочки раздача добавляется на паузе.

Место хранения — это папка `torrents` с подпапками `downloads/` (скачанное), `complete/` (готовые `.torrent`),
`removed/` (удалённые) и `.state/` (прогресс). Мест два вида: флешка `/mnt/usbN/torrents` и **внутренняя память
консоли `/data/pkg/torrents`** (системный установщик видит `/data/pkg`, вложенные папки тоже). Папка в памяти
консоли создаётся при первом запуске. Торрент, который вы положили в любую из этих папок руками, подхватывается и
скачивается туда же, где лежит. Между местами уже скачанные раздачи программа не переносит.

Для API: `POST /api/add?name=...&drive=internal|N&start=1|0` (см. таблицу). Без `drive` берётся `save_to` из
`config.txt` (по умолчанию `internal`).

**Свободное место.** Страница показывает свободное место по каждому месту хранения, а вверху красным предупреждает:
* если на флешке осталось меньше 2 ГБ или во внутренней памяти меньше 5 ГБ;
* если свободного места не хватает, чтобы докачать раздачу и оставить такой запас (у раздачи метка «low space»).

При запуске такой загрузки приходит уведомление `LOW FREE SPACE ...` и строка `WARNING: low free space ...` в
логе, но загрузка идёт. Исключение, защита системы: во внутренней памяти, когда свободно **меньше 1 ГБ**,
загрузки **не запускаются** (повтор через минуту; в логе `not starting ... console memory`), потому что забитая
доверху память ухудшает работу консоли. На флешке такого запрета нет.

## Настройки (необязательно) — /data/ps4torrent/config.txt

    max_parallel=3          # сколько раздач качается одновременно (1..25, по умолчанию 3; соединения делятся поровну, всего ~90)
    listen_port=6881        # порт для входящих соединений пиров (1024..65535), 0 = выключено
    save_to=internal        # куда класть торренты, добавленные через API без указания места: internal (по умолчанию) или usb
    resume_session=1        # 1 (по умолчанию): после перезапуска возобновлять то, что качалось; 0: не возобновлять
    autostart=0             # 0 (по умолчанию): раздачи после запуска и после добавления ждут на паузе, пока их не
                            # запустит пользователь; 1: стартуют сами
    web_token=ПАРОЛЬ        # пароль на управление (необязательно)

Файл перезаписывается целиком, когда настройки меняются через страницу или API (комментарии пропадут).

## Сеть и автозапуск GoldHEN

Если payload стартует автозапуском (сразу после включения консоли или выхода из режима покоя), сеть консоли ещё
не готова. Раньше слушающий сокет веб-сервера, созданный в этот момент, потом не принимал подключения: порт был
занят, программа работала, а страница не открывалась. Теперь программа следит за сетью:

* пока сети нет, проверка раз в 5 секунд, когда есть, раз в 30 (так же ловится смена адреса, например после DHCP);
* когда сеть появляется или адрес меняется, слушающие сокеты (веб-страница и входящие соединения пиров)
  пересоздаются, а на экране появляется уведомление `ps4torrent web: http://АДРЕС:8787/`;
* если адрес определить так и не удалось, через 60 секунд сокеты пересоздаются один раз в любом случае;
* если пересоздание не удалось, оно повторяется каждые 5 секунд.

В логе: `network: local address ...`, `network: listeners restarted (...)`, `network: connection lost`, а также первые
строки `http: connection #N from IP`: если страница не открывается, а таких строк нет, запросы до сервера не доходят.
В `/status` есть `net_ip` и `net_restarts`.

## Сон консоли, зависания и замена копии программы

**Сон консоли.** После сна процесс может остаться жив, но слушающие сокеты ломаются (адрес консоли при этом не
меняется): торрент качается, страница не открывается, `accept` возвращает ошибку. Защита:
* поток веб-сервера сам распознаёт повторяющиеся ошибки и пересоздаёт сокет (в логе: `http: the listening socket
  was broken (accept keeps failing, errno N), created a new one`);
* если главный цикл не работал дольше 8 секунд (сон консоли или зависший диск), после этого сокеты пересоздаются
  (`pause: the program was not running for N s ...`);
* раз в 10 минут сокеты тихо пересоздаются профилактически (без уведомления);
* то же для порта входящих соединений пиров (`incoming: accept keeps failing ...`).

Страница `/` отдаётся отдельными потоками и открывается даже тогда, когда главный цикл завис (но данные в ней
в это время не обновляются).

**Замена копии.** Если запустить программу, пока старая копия ещё работает (например, отправить новый ELF или
автозапуск сработал повторно), новая создаёт файл `/data/ps4torrent/quit.flag`, старая видит его (раз в секунду),
сохраняет прогресс и завершается, а новая занимает её место. На экране: `ps4torrent: replacing the running copy,
please wait...`. Ждать можно до 90 секунд (старая копия может быть занята зависшей флешкой); если она не
завершилась, новая отступает с уведомлением и ничего не ломает. (Копии старых версий этот флаг не знают:
их нужно остановить вручную, `/quit` или перезагрузка.)

**После сна: открытые файлы.** Флешка при засыпании и пробуждении может переподключиться, и открытые раньше файлы
становятся недействительными (запись возвращает ошибку, раздача останавливалась с `WRITE FAILED`). Теперь:
* ошибка записи или чтения не сдаёт раздачу сразу: файл закрывается, открывается заново, и операция повторяется
  один раз (в логе: `storage: write failed on ФАЙЛ (errno N), reopening the file and trying again`, при повторной
  неудаче `... still failing`; errno показывает настоящую причину);
* после паузы главного цикла (сон консоли) все открытые файлы закрываются заранее, а пиры, которых отметили
  недоступными из-за оборвавшихся соединений, снова допускаются: `recovery: N downloads will reconnect to peers,
  M open files were closed and will be reopened`; то же при возврате сети;
* если раздача всё же остановилась из-за ошибки записи, она повторяется через 20 секунд (а не 2 минуты):
  `INCOMPLETE (write failed), will retry in 20 s`.

**Ошибки записи и честные сообщения.** Если флешку вынули или она отказала посреди записи, раздача останавливается
(`piece N WRITE FAILED`, `INCOMPLETE (write failed)`, повтор через 20 секунд). Куски, которые стояли в очереди
позади неудавшегося и всё же записались, засчитываются (раньше они терялись), а неудавшиеся скачиваются заново.
Когда запись закончилась, в логе либо `disk writes of ... finished, progress saved`, либо
`WARNING: N verified piece(s) of ... could NOT be written to the drive ...: they will be downloaded again`.
У ошибок ввода-вывода (`errno 5, 6, 19, 2`) есть пометка `[the drive may have been disconnected]`.

**Часы консоли после сна.** В строке `pause: ... (monotonic N s, wall clock M s)` пишутся оба хода времени: счётчик без
скачков и системные часы. Если после сна системные часы консоли идут иначе (скачок назад или вперёд), это будет
видно по расхождению этих двух чисел. После паузы таймеры повторов у раздач, остановившихся из-за ошибок, сбрасываются
(они пробуют стартовать сразу), и флешки проверяются заново.

**Медленный диск.** Любая запись или чтение с флешки дольше секунды попадает в лог:
`storage: slow write of 8192 KB (piece N) took N ms` (не чаще раза в 5 секунд). Вместе со строками
`slow main loop: ... took N ms` это показывает, что именно останавливает программу.

## Память о том, что качалось (после перезапуска и сна консоли)

При пробуждении консоли автозагрузка GoldHEN запускает программу заново (в логе:
`the previous copy was asked to quit and replaced`), и без этой функции все задачи оставались бы на паузе. Поэтому
программа запоминает, **какие задачи должны качаться**: запущенные пользователем и не остановленные (не на паузе, не
завершённые). Список лежит в `/data/ps4torrent/session.txt` (внутренний диск, поэтому пропажа флешки его не
затрагивает) и обновляется через несколько секунд после любого изменения (переживает и `kill -9`).

После запуска такие задачи **возобновляются сами, но по очереди**: первая через 20 секунд, остальные с интервалом
15 секунд (чтобы не нагружать консоль всем сразу). До своей очереди они показываются как `queued`; в логе
`[resuming: it was downloading before the restart, starts in N s]`. Что остаётся на паузе:
* задачи, которые вы поставили на паузу (в том числе `pause all`);
* задачи, которые вы никогда не запускали (новые торренты ведут себя по правилу «автозапуск»);
* завершённые и удалённые задачи из списка убираются.

Если флешки в момент запуска нет, отметка о её задачах сохраняется, и они продолжатся, когда флешка вернётся.
Выключается галочкой «resume interrupted downloads after a restart» в настройках или `resume_session=0` в
`config.txt` (по умолчанию включено).

## Запуск: задачи ждут пользователя

После запуска программы (в том числе автозапуска GoldHEN после включения консоли) **ни одна раздача не стартует
сама**: все ждут на паузе (`paused`), на странице у каждой кнопка «resume», вверху «start all». Так при включении
консоли не начинается одновременная проверка и загрузка всех раздач (чтение флешки, подсчёт SHA-1, соединения),
из-за которой вся система подвисала. То же правило для раздач, добавленных позже (положили `.torrent` на флешку
или загрузили кнопкой «+ .torrent»).

* Включить прежнее поведение: флажок «start tasks automatically» в настройках на странице или `autostart=1`.
* Задача, которая работала, когда флешку вынули, после возврата флешки продолжается сама (это не запуск, а возврат).
* Недокачанные куски не теряются: пауза и перезапуск программы сохраняют их, они подхватываются при запуске задачи.
* Проверка уже скачанного (когда нужна) идёт «в полсилы»: около 40% времени работает, остальное отдыхает.
  Это снижает нагрузку на процессор и USB (на ПК: ~36% ядра вместо ~64%) ценой более долгой проверки.
  Проверка нужна только когда нет сохранённого прогресса (например, файлы положены вручную).

## Оставшееся время (ETA)

На странице рядом со скоростью: `ETA 1 h 23 min`. Считается как остаток / средняя скорость за последние
до 60 секунд (мгновенная скорость прыгает, потому что пиры отдают данные пачками). Первые ~10 секунд
после старта или продолжения показывается прочерк. Оценка тем точнее, чем стабильнее скорость:
если пиры приходят и уходят, время будет меняться.

## Входящие соединения (чтобы к нам могли подключаться пиры за NAT)

Большинство пиров не принимает входящие подключения (в логе это `connect timeout` / `error 61`),
поэтому исходящими соединениями мы достаём только малую часть раздающих. Если на роутере проброшен порт,
эти пиры сами подключаются к нам.

1. Закрепи за консолью постоянный IP-адрес (в роутере: резервирование DHCP по MAC-адресу консоли).
2. Пробрось на роутере **TCP-порт 6881** на этот IP (порт и номер в `listen_port` должны совпадать).
3. Проверь, пока качается раздача: на странице в шапке `incoming: N peers (port 6881)`, в логе строки
   `incoming peer ... connected`, в строке `alive:` счётчик `incoming: N accepted`.
   Снаружи порт можно проверить любым онлайн-сервисом проверки открытых портов.

Безопасность: принимаются только соединения BitTorrent для раздач, которые качаются прямо сейчас;
чужие, битые и молчащие закрываются (ожидание handshake 10 секунд, не больше 32 одновременно).
Страница управления (порт 8787) наружу пробрасывать НЕ нужно.

## Лог

    /data/ps4torrent/log.txt   (перезаписывается при каждом старте; вторая копия программы его не стирает)

* Раз в минуту в лог пишется строка `alive: ...` (число раздач, активных, скорость, пиковая память).
* Если программа упадёт, в лог попадёт строка `!!! FATAL signal ...` и на экране консоли
  появится уведомление `ps4torrent CRASHED`. Следом идёт строка `stack (...)` — цепочка вызовов,
  по ней находится место в коде (расшифровывается по файлу .elf той же сборки).
* Необработанное исключение C++ записывается как `std::terminate called: <причина>`.
* Ошибка при обработке одного запроса веб-страницы не останавливает сервер.

## Хранилище пропало: диагностика

Пока какое-то хранилище недоступно (флешку вынули, или консоль после сна её не вернула), страница пишет сверху
`Storage not found: /mnt/usb0 (N task(s) waiting)`, а программа раз в 30 секунд проверяет его «глазами своего
процесса» и пишет в лог строку вида:

    storage check #1: 3 task(s) wait for /mnt/usb0/torrents (offline for 40 s) | /mnt/usb0: PRESENT (mode 755, uid 0,
    gid 0), we can read it, 2 entries [torrents ...]; torrents folder PRESENT; filesystem exfatfs from /dev/da0s1 |
    /mnt: [usb0 ...] | devices: [da0 da0s1] | process: uid=0 euid=0 gid=0 jailed=0

Как читать:
* `ABSENT (errno 2 ...)` у точки монтирования: система её не показывает нашему процессу;
* `PRESENT`, но `we CANNOT read it (errno 13 ...)`: точка есть, но нашему процессу нет доступа (права);
* `PRESENT`, но `torrents folder ABSENT`: накопитель смонтирован, а папки `torrents` на нём нет;
* `NO ANSWER after N s (a file system call is HUNG ...)`: обращение к этой точке зависло (проверка идёт в отдельном
  потоке, поэтому программа остаётся отзывчивой);
* `devices: [...]`: есть ли вообще устройство накопителя (`da0` и т. п.) в системе;
* `process: uid=... jailed=...`: кем программа считается для системы. Та же строка пишется при запуске
  (`process: ...`) и после паузы/сна (`after the pause the process is: ...`): если они различаются, после сна у процесса
  изменились права или он оказался в «тюрьме», то есть видит файловую систему иначе, чем, например, FTP.

## Запись на диск (медленные флешки)

На некоторых флешках запись стоит около секунды **на каждый вызов**, почти независимо от размера (в логах это
`storage: slow write of 16 KB took 1500 ms`). Если писать в главном потоке, пока он ждёт диск, стоят и сеть, и
кнопки страницы, и вся система «подвисает». Поэтому:

* все записи на флешку выполняет **отдельный поток записи**: проверенный кусок передаётся ему, а главный цикл идёт
  дальше. Кусок считается скачанным, когда поток записи его записал (файл прогресса пишется тоже им, по порядку);
* запись идёт **крупными сериями**, а не мелкими блоками, и данные не пишутся дважды;
* **пауза и остановка ничего не ждут**: сеть закрывается сразу, статус сразу «paused», а недозаписанные куски и
  файлы прогресса дописываются в фоне (в логе: `... are still being written to the drive: the task is stopped,
  progress is saved when the writes finish`, потом `disk writes of ... finished, progress saved`). Если флешка
  зависла, программа остаётся отзывчивой; освобождается раздача, когда флешка ответит;
* **недокачанные куски** (часть куска, которая ещё не набралась целиком) сохраняются при паузе и остановке, а при
  запуске задачи подхватываются (`restored N partial pieces`). Во время работы они на диск **не пишутся**: раньше
  это делалось раз в 20 секунд сотнями мелких записей, и именно это вызывало зависания по минуте. Цена: при
  аварийном выключении питания или `kill -9` недокачанные куски (не больше нескольких МБ на раздачу) скачиваются
  заново, готовые куски не теряются. Данные из файлов проверяются по SHA-1 при завершении куска.

Если флешки нет, страница пишет `USB DRIVE NOT FOUND: tasks continue by themselves when it returns`, а в логе
раз в 30 секунд идёт `usb check: ...` (какие точки монтирования /mnt/usbN видны и есть ли в них папка torrents).
После сна консоли флешка может возвращаться несколько минут: задачи продолжатся сами.

## Ограничения памяти при разборе .torrent

У процесса на консоли обычной памяти около 10 МБ, разбор `.torrent` занимает примерно 1,3 КБ на файл раздачи.
Раздача на ~5000 файлов уже занимает 6,5 МБ, а на ~10000 не помещается. Такие файлы отклоняются с сообщением
`not enough memory to load it` (в логе и в ответе `/api/add`), остальные раздачи работают как обычно.
Файлы `.torrent` больше 2 МБ пропускаются сразу.

## Отзывчивость интерфейса

* Запросы к трекерам идут в фоновых потоках: раньше на время ответа трекера (бывает несколько секунд) замирала
  вся программа, и кнопки страницы отвечали с задержкой.
* Каждое HTTP-соединение обслуживается в своём потоке (не больше 12 одновременно): пустые «заготовленные»
  соединения браузера больше не задерживают остальные запросы.
* Состояние обновляется сразу после любой команды, а не раз в секунду; список флешек и свободное место
  обновляются при сканировании (раз в 10 секунд).
* Если какой-то этап главного цикла занял дольше 0,3 секунды, в лог пишется `slow main loop: <этап> took N ms`
  (этапы: commands, deletions, scan_usb, downloads, snapshot). Если команда не применилась за 3 секунды:
  `command ... was not applied within 3 s`. Пришли такие строки, если интерфейс снова будет «залипать».

## Что писать в лог и как читать

* `piece N stalled for 46 s, re-requesting missing blocks (keeping 300 of 512)` — пир замолчал; уже
  полученные блоки куска сохранены, недостающие запрашиваются у других. Кусок выбрасывается целиком
  только если 10 минут ничего не приходит (`got nothing for ... dropping it`).
* Раз в минуту по каждой раздаче: `connections closed in the last 60 s:` и список причин, например
  `connecting: connect failed (error 111)` (порт закрыт), `connecting: connect timeout` (недоступен,
  обычно за NAT), `handshake: closed by peer`, `handshake: handshake rejected (...)` (возможно, пир требует
  шифрование), `active: request timeout`. По этому списку видно, почему из 30 пиров работают 3.
* `tracker http://... failed: <причина>` — трекер не ответил или ответил ошибкой.
* `incoming peer ip:port connected` — пир подключился к нам сам (значит, проброс порта работает).
* `handshake: connected to ourselves` — трекер вернул наш же адрес; соединение закрыто.
* Раздача считается «зависшей» (и перезапускается через 2 минуты) только если 5 минут не приходит
  вообще никаких данных (раньше — если 5 минут не завершался ни один кусок).

## Память (важно для разработки)

На консоли обычный malloc/new суммарно даёт процессу всего ~10 МБ (замер memtest), а mmap — сотни МБ.
Поэтому буферы кусков раздач (8-16 МБ) выделяются через mmap (класс BigBuf в swarm.cpp).
Всё остальное должно оставаться маленьким. В минутной строке лога `alive:` виден пик памяти.

## Проверка: вшитый в payload файл (временная сборка)

Нужна, чтобы выяснить, принимает ли GoldHEN большой ELF (сюда позже попадёт PKG интерфейса).

    python3 make_test_blob.py 7                      # создаёт blob.bin (7 МБ случайных данных)
    make BLOB_FILE=blob.bin ELF=ps4torrentd-blob7mb.elf

При запуске программа считает SHA-1 вшитого файла, сверяет его с эталоном (посчитанным при сборке), записывает
его в `/data/ps4torrent/blob_test.bin` и читает обратно. Результат: строки `blob: ...` в логе и уведомление
`embedded 7 MB file: intact, disk write OK`. Обычная сборка (`make`) этот код не содержит.

## Чего пока нет

* раздачи данных другим пирам (клиент только скачивает; входящие соединения нужны, чтобы достучаться до пиров);
* обмена пирами (PEX), UDP-трекеров (только http://), DHT и magnet-ссылок;
* установки PKG из клиента (в старой версии это было; ставить нужно системным установщиком);
* ограничения скорости, выбора файлов внутри раздачи;
* автозапуска после перезагрузки консоли (ELF нужно отправлять заново).
