# HANDOFF: ps4torrentd (BitTorrent-клиент для PS4)

Файл для продолжения работы в новом чате. Прочитайте его, потом `README.md` (описание для пользователя) и `tests/README_TESTS.md`.

## 1. Что это
Пайлоад (ELF) для PS4 с GoldHEN: скачивает торренты на USB-накопитель или во внутреннюю память консоли, управление через веб-страницу
(порт 8787). **Только скачивание, раздачи нет** (отложена по просьбе пользователя). Подпись внизу страницы:
`ps4torrent v<версия> Created by SergioPoverony and Mr.Claude`. Текущая версия: **1.4.1.4** (1.2.0.0 была переходной; 1.3.0.0 добавила выбор файлов; 1.3.0.1: сборка на свежем SDK; 1.3.0.2: завершённые раздачи остаются в списке; 1.4.1.4: исправлен краш при удалении раздачи с недописанными кусками (освобождённая память) и «зависание» на 80–160 с при удалении больших файлов (теперь в отдельном потоке); 1.4.1.3: расширенный диск `ext0`/`ext1`, лимит параллельных закачек 25 (по умолчанию 3) с общим бюджетом соединений, короткие таймауты молчащих пиров, на экране только реально отдающие пиры, меньше памяти (чистка `failedAt`, кандидатов не больше 150, входящих сверх лимита только +3); 1.4.1.2: исправлена полная проверка у задач со снятыми файлами, лимит активных кусков 32 МБ с общим пределом 128 МБ, компактная таблица кусков (куча), мягкая реакция на `bad_alloc`, сглаженная скорость на странице).

## 2. Как работать с пользователем (важно)
* Общение **по-русски**, кратко, сначала главное. Пользователь не программист: объяснять простыми словами, честно писать, что
  проверено и что нет («проверено на ПК, на консоли не запускалось»). Не придумывать: чего не знаешь про консоль, так и сказать.
* Ассистент собирает ELF, пользователь сам заливает его на консоль и присылает `log.txt` и описание. Ответ по логу: что видно,
  что гипотеза, что не знаю.
* «Пока только вопрос» = без правок. «Тесты делать не надо» = не запускать. Не добавлять функции, о которых не просили
  (можно предложить и спросить). Один вопрос в конце, не больше.
* Каждая выдача: ELF + zip исходников + README (+ HANDOFF) через `present_files` (иначе пользователь не видит файлы).
* **Версия:** при каждой правке и пересборке увеличивать последнюю цифру `APP_VERSION` в `main.cpp` (1.4.1.2 -> 1.4.1.3 -> ...; версию 1.4.1.2 назвал сам пользователь);
  при крупных изменениях менять и старшие цифры.
* Перед выдачей прогонять тесты (см. `tests/README_TESTS.md`), новую функцию покрывать новым тестом. Тесты уже не раз находили
  настоящие ошибки (дыры в файлах при возврате снятого файла, потеря кусков при ошибке записи, зависание очереди).

## 3. Среда и сборка
* Консоль: PS4, прошивка **13.52**, GoldHEN **v2.4b18**, IP 192.168.0.24. Проверено только на ней. **Ограничение по прошивкам** задаёт стартовый код SDK (см. ниже, «Прошивки»), а не наш код.
* Сборка у пользователя: Ubuntu в VirtualBox, `ps4-payload-sdk` (john-tornblom, `/opt/ps4-payload-sdk`), clang-18, команда `make` в
  папке проекта; заливка: `/opt/ps4-payload-sdk/bin/orbis-deploy -h 192.168.0.24 -p 9090 ps4torrentd.elf`.
* **SDK:** `https://github.com/ps4-payload-dev/sdk` (john-tornblom; раньше `john-tornblom/ps4-payload-sdk`). С версии 1.3.0.1 собираем на
  `master` коммит `573b4a0` (2026-09-22, «Add 14.00 offsets»). Как поставить в песочнице (root, без sudo): `git clone --depth 1 <url> sdk_src;
  cd sdk_src; make; make DESTDIR=/tmp/sdk_new install; pip install cmake --break-system-packages; PS4_PAYLOAD_SDK=/tmp/sdk_new MAKEFLAGS=-j1
  bash libcxx.sh` (**libc++ нужна обязательно**: без неё не находятся заголовки `string`, `functional`, `exception`; скрипт скачивает LLVM 15.0.7 и
  собирает `libc++.a libc++abi.a libunwind.a`, минуты). Затем `export PS4_PAYLOAD_SDK=/tmp/sdk_new; make` в проекте.
  Старая копия (`/tmp/sdk/ps4-payload-sdk`, таблица прошивок только до 13.50) использовалась до 1.3.0.0; у пользователя в `/opt/ps4-payload-sdk`
  может быть другая версия: ELF собирает ассистент, так что важна именно сборка ассистента.
* Результат: `ps4torrentd.elf` (~1,3 МБ, картинки вшиты). Проверка перед выдачей: в ELF нет тестовых путей (`strings -a | grep /tmp/ft`
  = 0), `NEEDED` библиотек 3 (libkernel_web, libSceLibcInternal, libSceNet), свежая сборка из zip даёт идентичный ELF (`cmp`).
* Интерфейс страницы написан в `page.html` (в zip его нет отдельно: он вшит в `main.cpp` как `PAGE = R"HTMLPAGE(...)HTMLPAGE"`;
  копия лежит в `tests/page/page.html`). Правка страницы: изменить текст между `R"HTMLPAGE(` и `)HTMLPAGE"`.

## 4. Исходники (порядок сборки)
`main.cpp assets.S writer.cpp incoming.cpp log.cpp net.cpp bencode.cpp sha1.cpp torrent.cpp tracker.cpp storage.cpp download.cpp
resume.cpp swarm.cpp` + `blob.S` (необязательный тестовый блок). Заголовки `*.h`, `bigbuf.h`. Картинки в `assets/`:
`favicon.ico`, `title.png` (логотип шапки), `notify64.png` (иконка уведомлений 64x64); вшиваются через `assets.S`.

| Файл | Роль |
|---|---|
| `main.cpp` | всё главное: планировщик, сканирование накопителей, HTTP-сервер и страница, сеть, сон, сессия, выбор файлов |
| `writer.cpp` | отдельный поток записи на диск (главный цикл не ждёт диск) |
| `swarm.cpp` | движок BitTorrent (неблокирующий select), выбор кусков, проверка |
| `storage.cpp` | файловый ввод-вывод, замок, повтор при устаревшем дескрипторе, пропуск снятых файлов |
| `resume.cpp` | файлы прогресса `.have`, `.part`, выбора `.sel` (есть варианты с явным каталогом для потока записи) |
| `download.cpp` | проверка уже лежащих данных (Rechecker) |
| `incoming.cpp`, `tracker.cpp`, `net.cpp`, `torrent.cpp`, `bencode.cpp`, `sha1.cpp`, `log.cpp` | прочее |

## 5. Что умеет (по версиям)
* Скачивание на `/mnt/usbN/torrents` и `/data/pkg/torrents` (память консоли), прогресс на накопителе, SHA-1, докачка, недокачанные
  куски сохраняются при остановке, входящие соединения (порт 6881), асинхронные запросы трекера.
* Автозапуск по умолчанию **выключен**; **память о сессии** (1.2.0.0): задачи, которые качались, после перезапуска возобновляются
  по одной (первая через 20 с, дальше раз в 15 с), файл `/data/ps4torrent/session.txt`. Настройка `resume_session`.
* Сеть: слежение за адресом, самолечение сокетов, восстановление после сна, замена старой копии новой (`quit.flag`).
* Поток записи (медленные флешки: ~1 с на вызов), пауза не ждёт диск, честные сообщения при потере записи.
* Несколько накопителей, создание `torrents` при добавлении, предупреждения о месте (флешка < 2 ГБ, память < 5 ГБ), защита
  системного диска (в памяти консоли < 1 ГБ свободно: загрузки не запускаются).
* Страница: только тёмная тема, логотип, значок, диалог добавления (Cancel слева, Next/Download справа), **выбор файлов**
  (1.3.0.0): окно со списком, кнопка `files` у задач, `skip=` в API. Уведомления с иконкой (через `http://127.0.0.1:8787/notify.png`,
  способ проверен пользователем; сообщения о сбое идут со стандартной иконкой).
* **Завершённые загрузки** (1.3.0.2): после перезапуска читаются из `complete/` (`add_item(..., fromComplete=true)`), остаются в списке до `remove` /
  `remove + files`; лимит `MAX_DONE_ITEMS=100` / `MAX_DONE_FILES=3000` (память ~10 МБ); `.sel` (выбор файлов) сохраняется после завершения и
  удаляется только при удалении или повторном добавлении того же `.torrent`.
* **Память (1.4.1.2):** куча на консоли ~10 МБ. `PieceTable` в `swarm.cpp` создаёт запись `PieceBuf` (144 байта) только для кусков в работе и
  освобождает её (`release`) после записи/сброса куска; раньше массив на все куски раздачи съедал ~3,5 МБ на раздачу в 26 тысяч кусков.
  Буферы данных кусков в `mmap` (`BigBuf`), общий счётчик `bigbuf_total()`; предел `MAX_BIGBUF_TOTAL` 128 МБ, на раздачу `SWARM_ACTIVE_BYTES`
  32 МБ (минимум 2 куска всегда). `std::bad_alloc` в главном цикле: `Swarm::trim_memory()` закрывает соединения, переподключение через ~5 с,
  после 5 случаев за 10 минут чистая остановка. 
* **Версия 1.4.1.3:** (а) `slot_mount()`/`SLOT_COUNT`: номера накопителей 0..7 = `/mnt/usbN`, 8..9 = `/mnt/ext0..1` (`EXT_BASE`), в JSON `kind` = `usb`/`ext`; (б) `MAX_PARALLEL_LIMIT`=25, `CONN_BUDGET`=90: `perConns = clamp(90 / активных, 4, 30)`, входящих сверх лимита +3 (было +10); (в) таймауты в `swarm.cpp`: пир, державший запросы, молчит дольше `PEER_SILENT_SECONDS`=15 с с последнего блока (или с отправки старейшего запроса) → закрыт; было «30 с с запроса», что рвало медленных, но живых; `PIECE_STALE_SECONDS` 20, `STALL_RESTART_SECONDS` 30, подключение и handshake по 10 с; (г) `SwarmStatus.sending` = пиры, приславшие блок за последние 10 с: именно оно показывается как «peers» на странице (`ready` остаётся в логе: `peers N (ready R, sending S)`). Проверено на ПК; на консоли не запускалось.
* Диагностика пропавшего хранилища: строки `storage check #N` раз в 30 с (точка монтирования, ошибки, устройства, uid/jailed).

## 6. Важные факты и решения
* **Прошивки (стартовый код SDK, `crt/kernel.c`):** в каждую нашу программу линкуется `__kernel_init`, его вызывает `_start` до `main`. Он читает
  версию прошивки (sysctl) и через системный вызов `kexec` (его даёт загрузчик, GoldHEN) находит адреса в ядре. Версии **ниже 3.50** не
  поддерживаются (`-ENOSYS`); для явно перечисленных версий (3.50 ... 14.00, в том числе 13.52) берутся готовые числа, для более новых идёт поиск по
  шаблонам. **Если инициализация не удалась, `_start` завершается с ошибкой ещё до `main`: тихо, в нашем логе ничего нет.** Это первое, что подозревать
  при «не стартует». Старый SDK (до 1.3.0.0) знал явно только до 13.50, на 13.52 работал через поиск по шаблонам.
* `malloc` на консоли ~10 МБ: буферы кусков идут через `mmap` (`BigBuf`). Не выделять большое в куче.
* Запись на флешку пользователя медленная; всё, что трогает диск, не должно блокировать главный цикл (поток записи, потоки проверки).
* Сон консоли: счётчик `CLOCK_MONOTONIC` сон **не считает**, системные часы считают; пауза определяется по большему из двух.
  После сна автозагрузка заново запускает программу, она просит старую завершиться и занимает место. Процесс после сна тот же (uid=0).
* Пропажа флешки после сна на реальном железе **больше не воспроизводится** после правок (поток записи, замена копии, память сессии);
  точная причина не выяснена. Если вернётся: смотреть `storage check`, `process:`, `after the pause the process is:`.
* **Выбор файлов:** `DownloadState.skip/needLeft` (куски целиком в снятых файлах не качаются, `needLeft==0` = готово), `Storage`
  не пишет и не создаёт снятые файлы, `Item.fileSel/skipPiece/inexactPiece/wantBytes`. Пограничные куски скачиваются целиком.
  **Возврат снятого файла:** пограничные куски объявляются нескачанными (`try_apply_selection`, прогресс перезаписывается, не
  объединяется), и только когда у задачи нет работающей загрузки и недописанных записей (zombie); задача с отложенной сменой
  выбора (`selPending`) не стартует. Выбор у завершённой задачи менять нельзя. Спот-проверка пропускает «неточные» куски.
* Заголовки HTTP: страница, картинки (`/favicon.ico`, `/logo.png`, `/notify.png`) без пароля; весь API с паролем, если задан `web_token`.
* Файл прогресса при записи **объединяется** (`resume_merge_save_at`), для замены нужен `resume_save_at`.

## 7. HTTP API (порт 8787)
`GET /status`, `/api/config`, `/api/set?max_parallel=&listen_port=&autostart=&save_to=&resume_session=`, `/api/pause|resume?hash=`,
`/api/pause_all|resume_all`, `/api/delete?hash=H40[&files=1]`, `POST /api/add?name=&drive=internal|N&start=1|0&skip=3,5-9`,
`/api/files?hash=`, `/api/select?hash=&skip=`, `/quit`. Подробности и поля: `README.md`.

## 8. Пути на консоли
Лог `/data/ps4torrent/log.txt`; настройки `config.txt`; `session.txt`; `quit.flag`. Накопитель: `<корень>/torrents/{*.torrent, downloads/,
complete/, removed/, .state/<хэш>.have|.part|.sel}`; корни `/mnt/usbN/torrents` и `/data/pkg/torrents`.

* **Версия 1.4.1.4 (по логу пользователя со SIGSEGV):** (а) `retire_item()`: при удалении раздачи, которая как «зомби» ещё дописывается потоком записи, её `Item` (там `Torrent`, на который ссылаются `Swarm` и `Storage`) не освобождается, а передаётся зомби (`Zombie::orphan`) и удаляется вместе с `Job` в `reap_zombies`; раньше был `heap-use-after-free` (`Storage::io_impl`), краш происходил позже, в чужом `free`. (б) Удаление файлов (`unlink`) вынесено в поток `delete_thread` (`DelJob::stage` атомарный: 0 ждёт, 1 работает, 3 готово); раньше unlink файла в десятки ГБ блокировал главный цикл на 80–160 с («command … was not applied within 3 s», «pause: the program was not running for 81 s», страница «не удаляет»). Тесты: `delzombie_test.py` (на старом коде воспроизводит ASAN-ошибку, на новом 13/13), `slowdel_test.py` (хук `/tmp/ft/unlink_cost`, 8/8), ThreadSanitizer 0 отчётов.
* **Как расшифровать краш из лога** (`!!! FATAL signal 11 ... rip 0x40837e`): собрать тот же код с `-g` (`make ELF=/tmp/dbg.elf CXXFLAGS="-std=c++17 -O2 -Wall -g"`; секция `.text` совпадает с выданным ELF, проверить `llvm-objcopy -O binary --only-section=.text`), затем `llvm-symbolizer --obj=/tmp/dbg.elf -f -i <rip - 0x400000>`. Если падение в `free`/`delete`, виновата порча кучи раньше, искать ASAN-тестом.

## 9. Тесты
**Заметка по тестовой среде:** после очистки `/tmp` данные тестов нужно создавать заново: `python3 mk.py` делает только Game One и Small; Big8M (8 МБ куски, файлы `big.bin` 26000000 и `extra/more.bin` 9000000, `mk.PL=8388608`) и Many (`many.bin` 70000000, куски 16384) создаются вызовом `mk.make(...)`; хэш Big8M прописан в `wr_test.py`/`auto2.py` и меняется при пересоздании (`sed`). Перед `auto_run.sh` и др. удалять `/tmp/ft/internal`. `build_tests.sh` теперь с `-DEXT_BASE`; в нём кавычки удвоены (`\\\"`), иначе `-D` макросы не собираются.
Лежат в `tests/` (см. `tests/README_TESTS.md`): наборы на ПК с санитайзером памяти, подставные пути `/tmp/ft/...`, тестовый сид
(`seeder.py`), страницу проверяет Node (`jstest2.js`, `jstest5.js`). Последний прогон перед 1.3.0.0: API 30, запуск 16, удаление 15,
перезапуск 13, зависший диск 13, хранилище 27, накопители 19, выбор файлов 25, завершённые в списке 21, страница 20+30, сессия 17/18 (на 1.3.0.2 и 1.4.1.2 не прогонялась: её проверка «после перезапуска всё на паузе» теперь видит завершённые). Для 1.4.1.2 добавлены: память 15/15, полная проверка 8/8, страница 34/34; ThreadSanitizer 0 замечаний (известный артефакт теста).
**Не прогонялись на 1.3.0.0:** ThreadSanitizer, наборы сети, самолечения, замены копий, устаревшего дескриптора.

## 10. Не сделано / идеи (по порядку важности для пользователя)
* **Раздача (upload)** не реализована, отложена. Если вернутся к ней: ответ на `request`, свои куски в bitfield, чтение с диска отдельным
  потоком, ограничение скорости, статистика трекеру (сейчас всегда `uploaded=0`), выключена по умолчанию. Вопрос пользователю:
  раздавать только после загрузки или и во время.
* Версия прошивки в логе (отложено), DHT/magnet/UDP-трекеры/PEX, ограничение скорости скачивания.
* PKG-менеджер (`pkgmgr.*` писался, но в сборку не включён), будущее отдельное PKG-приложение.
* Выбор файлов: возможное улучшение: кнопка «Back» во втором окне; показ, сколько уже скачано по каждому файлу.
* Мелочь: уведомление о дубликате торрента (файл сохраняется, в списке ничего не появляется, страница пишет «Added»).

## 11. С чего начать в новом чате
1. Распаковать `ps4torrentd-src.zip`, найти SDK, `make` (должно собраться без предупреждений).
2. `cp -r tests/ft/* /tmp/ft/`, `bash tests/build_tests.sh`, подготовить данные (`mk.py`), прогнать нужные наборы.
3. Спросить у пользователя, что дальше; не начинать с новых функций без запроса.
